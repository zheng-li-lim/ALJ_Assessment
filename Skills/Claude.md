### SKILL: Frontend-Modified
**File:** `skills/SKILL-Frontend-Modified.md`
**Trigger:** Any frontend code — HTML, CSS, JavaScript UI components. Invoked every session before writing any frontend code, no exceptions.

**Summary of rules this skill enforces:**

Before writing a single line of frontend code, commit to a bold aesthetic direction specific to this project. Answer: What problem does this interface solve? Who uses it? What makes it unforgettable?

For this project the answers are fixed:
- **Purpose:** Executive intelligence briefing for a Chairman and CSO at a global automotive conglomerate
- **Tone:** Luxury/refined editorial — think Financial Times meets The Economist. Authoritative, precise, unhurried. Not dark/moody, not brutalist, not playful.
- **Differentiation:** The one thing someone will remember is that this looks like a real intelligence product, not a dashboard built by a developer.

**Execution rules:**
- Typography: Choose fonts with editorial personality. Playfair Display for display headings (already specified in brand). For body, use a refined serif or geometric sans — not Inter, not Roboto, not Space Grotesk as defaults. The font pairing must feel intentional and context-specific.
- Colour: Use the ALJ palette from this file. Dominant Prussian Blue with Gold accents. Take a clear position — do not distribute colours timidly.
- Motion: CSS-only animations on `transform` and `opacity` only. One well-orchestrated page load with staggered reveals. No `transition-all`.
- Spatial composition: Unexpected layouts where appropriate. Generous negative space. Clear typographic hierarchy with dramatic scale contrast between display and body text.
- Backgrounds: Create depth — subtle grain, layered transparency, or tonal variation. Never flat solid colours on large surfaces.
- Every clickable element: hover, focus-visible, and active states. No exceptions.
- Never use generic AI aesthetics: no purple gradients on white, no Space Grotesk defaults, no predictable card grids without intentional spatial decisions.

### SKILL: Humanizer
**File:** `skills/SKILL-humanizer.md`
**Trigger:** Any time the app generates written content — news summaries, executive summaries, action text, so-what fields, agent output text displayed to the user. Apply before rendering any Claude API text output to the UI.

**Summary of rules this skill enforces:**

All text generated by the Claude API and displayed to the user must pass these checks before rendering:

**Banned words — remove and restructure, do not substitute:**
- Filler openers: Certainly, Of course, It is worth noting that, It is important to, Needless to say
- Vague nouns: Stakeholders, Ecosystem, Landscape (metaphorical), Synergies, Learnings, Alignment
- AI slop verbs: Leverage, Utilise, Facilitate, Ensure, Drive (growth), Unlock, Harness, Delve into, Navigate (metaphorical)
- Decorative adjectives: Robust, Comprehensive, Seamless, Holistic, Cutting-edge, Game-changing, Transformative, Nuanced, Dynamic, Unique

**Structural rules:**
- Conclusion first — never build to a point
- One idea per sentence — split anything with more than two clauses
- Active voice — name the specific actor
- Numbers anchor claims — replace vague qualitative language with specific figures
- So-what is explicit — every item ends with a concrete implication naming the specific ALJ business unit

**For the so-what field specifically:**
- Good: "Jameel Motors should brief its KSA dealer network on the new EV import incentive before the Q3 inventory order is placed."
- Bad: "This is relevant to ALJ's mobility business and should be monitored."

Apply the Humanizer as a post-processing pass on all Claude API text outputs before they appear in the UI. The scraper classification prompt and builder summary prompt should instruct Claude to write in this style from the start — but run a check pass regardless.

### SKILL: email-html-mjml
**File:** `skills/email-html-mjml.md`
**Trigger:** Invoked only when the "Share as Email Newsletter" button is clicked and the email export is being generated. Do not invoke for any other purpose.

**Summary of rules this skill enforces:**

When generating the email newsletter export:

- Use MJML 4.x framework. All visual content inside `<mj-column>` inside `<mj-section>`. No nesting of sections.
- Compile with `npx mjml --config.minify=true` — mandatory for Gmail 102KB clip limit and iOS column stacking fix.
- All styles inline via `inline="inline"` on `<mj-style>` — Gmail strips `<head>` CSS.
- Use `<mj-font>` for web fonts to prevent Outlook's Times New Roman fallback.
- Every `<mj-image>` must have `alt`. Always set `<mj-title>`.
- Background images: VML only generated for `<mj-section>` and `<mj-hero>` — nowhere else.
- No JavaScript of any kind — completely blocked in all email clients.
- Deliver both `.mjml` source and compiled `.html`.

**ALJ email structure (single-column, 600px):**
1. Header: ALJ logo (white on Prussian Blue `#002e5d` background), edition date
2. Executive summary section (teal left border `#51859a`)
3. Highlights list (anchor links become plain text in email — style as a scannable numbered list)
4. Article cards (one per section, area of interest tag, headline, summary, so-what panel, action badge)
5. Footer: disclaimer text, "Content generated by AI for strategic planning purposes. Verify before acting."

**Brand colours for email (inline only):**
- Background: `#f7f4ef`
- Header background: `#002e5d`
- Accent/teal: `#51859a`
- Gold: `#c9a84c`
- Red/escalate: `#d22630`
